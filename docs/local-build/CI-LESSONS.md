## Before dispatching or pushing a workflow change

Run `45520810311` passed both complete native ARM fault harnesses, the prior timing regressions and DXMT compilation, then failed a combined Windows-Vulkan assertion because public 0.1.712 omits `app/Madeira/vulkan/README.md` (already in the known optional-doc list). Split the documentation assertion from the strict DLL-ignore and Xcode resource-bundling assertions. Only explicit `--public-source` mode may report that exact absent **untracked** README as a documentation-only skip; tracked missing files, wrong resources and all functional checks still fail. Local strict-mode, missing-tracked-doc and removed-bundle-resource negative controls passed. Keep the Vulkan source/packaging contract early in Linux, and audit literal `is_file`/`exists` dependencies as well as reads; presence checks can intentionally assert absence, so report unresolved ones for review rather than inventing a fatal dependency. Never fabricate an upstream README or skip the whole functional suite for this case.

Run `45508567740` passed the complete controlled-clock interpolation harness, including the 30 ms host-delay case, then reached the build-591 regressions. The fault-guard guest-RIP harness redefined Darwin ARM get/set accessor macros over a synthetic context; the newer SDK macros expanded against the wrong fields and stopped compilation under `-Werror`. Undefine the SDK accessor macros before installing test stand-ins, including the adjacent guest-progress harness. Audit all host tests for this family (two additional PC-accessor definitions needed explicit undef). Preserve all off/on thresholds, ASan and UBSan. `check-host-arm-accessors.py` runs 68 real source/runtime checks with preexisting conflicting SDK macros and a collision negative control in Linux; run the two complete native fault harnesses early on macOS. The 32-bit farm completed and was cached in run 55.

Run `45506929959` verified the original six native VideoToolbox harness phases with the controlled clock, plus iOS compilation and Swift checks. The added 30 ms host-delay case exposed another test-input race: the model could finish loading during frames intended only to warm up, changing surface numbering and the FPS average. Gate the fake model readiness until those loading frames have been submitted in phases 2/3; keep the production model lifecycle unchanged. This early regression failed in minutes rather than after the full build.

Run `45494579844` passed converter recovery and all six source manifests, then failed the VideoToolbox interpolation behaviour harness. Its 12/20/33/40 ms game-frame inputs used host sleeps, so scheduling delays changed the simulated FPS and inserted false stalls; the automatic diagnostic rerun failed a different subset. Keep all exact picture-count/order/error assertions, but compile the unchanged production interpolation block with a controlled nanosecond Mach/Quartz clock in this harness. Worker/model/GPU waits remain real. Explicitly advance simulated time for frames and intentional stalls, remove timing-based retries, and repeat the complete 25/50 FPS phase with 30 ms of extra host delay. `check-vt-interp-clock.py` exercises production picture decisions, backlog suppression, real host delay and a missing-clock-advance negative control in Linux. Run the full native harness immediately after submodules and Xcode selection, before expensive builds; source/C checks in WSL do not establish Objective-C/iOS success.

1. Read the current handoff and this file. Inspect the target branch SHA, active/queued runs and actual artifacts. A workflow push can already start the build; never immediately add a manual dispatch. Do not cancel other builds.
2. Compare the new workflow with the verified successful baseline, including the number of tests and toolchain versions. Check formatting assertions across the whole suite when adding fixture guards. Fix the family of proven failures together.
3. Run `python3 tests/host/check-workflow-commands.py`, `python3 tests/host/check-ipa-workflow-contract.py` (for this unsigned branch), `python3 tests/host/check-vk-fps-pacing.py`, `python3 tools/check-vendored-manifests.py --index` after staging, `python3 tools/ci-preflight-host-fixtures.py --strict`, syntax checks and `git diff --check`. CI checks vendored checkout bytes without `--index`. On this Windows machine the portable compiled pacing test can run with `wsl -d PlayportBuild -- python3 tests/host/check-vk-fps-pacing.py`; WSL has `cc` and `python3`, but cannot create the iOS IPA. Audit bare `assert` statements and workflow variable names beyond `wf`/`ci` as well as `check(...)` calls; production publication contracts also need an explicit mode. Put new, focused regression checks early on the appropriate runner. Source checks on Windows are not Swift/C/iOS execution evidence.
4. Keep Xcode/SDK selection, source pins, compatibility patches and cache keys unless evidence requires a specific change. Record component compiler majors: a floating Homebrew formula can change while app source remains the same. GitHub caches are branch-scoped; a new feature branch may have to rebuild dependencies even when another feature branch built them before.
5. On failure, read the failed step's full log. Distinguish a wrong workflow assertion, missing optional fixture, unsupported compiler and actual compiler/runtime failure. Preserve successful caches before retrying. Check for an active or successful matching run again immediately before starting another.
6. Require the expected IPA artifact, not just a green job. Verify both payloads' bundle IDs, version and `MadeiraCommit`, ZIP integrity, touch-acceleration symbol, Cloud-migration log marker, and `[tc-exec-recheck]` in both shipped FEX DLLs. `tools/verify-upstream-cloud-ipa.py` performs this for the 0.1.712 test build; update its version expectation deliberately for future versions.
7. Report the actual run URL, artifact URL, source SHA and real test results, including explicit skips. Before any device test, back up **both** `wine/drive_c/users/mythic` and `mobile`. A per-file newer timestamp is not proof of a coherent game save set; do not automatically resolve Steam Cloud conflicts.
